# QA

Output quality control — did the result meet the task's Definition of Done,
not "did the code run without erroring" (that's `tests/`, existing, untouched).

Each task that reaches `status: review` or `status: done` should have its DoD
checklist (copied from the owning playbook) verified here before being marked
complete, per Quality Control in the MILI operating principles: a task is not
done because an action was performed — it's done when the outcome exists,
has been checked, and meets the Definition of Done.
